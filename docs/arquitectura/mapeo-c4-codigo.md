# Mapeo de componentes C4 a paquetes Java

Este mapeo corresponde a los componentes C4 descritos para Consultas SRI ANT. Los paquetes marcados como futuros son destinos lógicos; no representan funcionalidades ya implementadas. El diseño de IcePanel no se modifica.

| Componente C4 Nivel 3 | Ubicación Java prevista | Estado en este bloque |
|---|---|---|
| Aplicación backend Spring Boot, desplegable como una unidad | `ec.edu.udla.consultas` y `ConsultasApplication` | Base creada en el Bloque 1. |
| Adaptador REST de entrada de contribuyentes | `ec.edu.udla.consultas.contribuyentes.adapter.in.rest.ContribuyenteRestController` | Implementado: `POST /api/v1/contribuyentes/consultas`; email solo se valida. |
| DTOs de entrada y salida de contribuyentes | `ec.edu.udla.consultas.contribuyentes.adapter.in.rest.dto` | Implementados; la respuesta mapea el dominio y no devuelve el email. |
| Adaptador REST de entrada de vehículos | `ec.edu.udla.consultas.vehiculos.adapter.in.rest.VehiculoRestController` | Implementado: `POST /api/v1/vehiculos/consultas`; devuelve también listas vacías como HTTP 200. |
| DTOs de entrada y salida de vehículos | `ec.edu.udla.consultas.vehiculos.adapter.in.rest.dto` | Implementados; conversión de dominio a tipos JSON en el límite HTTP. |
| Adaptador REST de entrada de puntos de licencia | `ec.edu.udla.consultas.puntos.adapter.in.rest.PuntosLicenciaRestController` | Implementado solo con perfil `local-simulation`; el servidor queda enlazado a loopback y devuelve resultados `SIMULATED`, nunca consulta ANT. |
| DTOs REST de puntos de licencia | `ec.edu.udla.consultas.puntos.adapter.in.rest.dto` | Implementados para la entrada `cedula` estructural y el sobre normalizado `data.totalPuntos` + metadata de origen/fecha/antigüedad. No afirman el esquema real ANT. |
| Respuestas comunes y metadata API | `ec.edu.udla.consultas.shared.api.ApiResponse` y `ApiMeta` | Implementadas para respuestas exitosas SRI, con `requestId`, `source` y `retrievedAt`. |
| Manejo transversal de errores y request IDs | `ec.edu.udla.consultas.shared.api` | Implementado: validación/JSON, ausencia confirmada, clasificación no natural o indeterminada, fallos SRI y error interno. |
| Dominio de contribuyentes | `ec.edu.udla.consultas.contribuyentes.domain.Contribuyente`, `TipoPersona` y `ValorCampoContribuyente` | Implementado: conserva propiedades SRI permitidas, tipos JSON y estructuras anidadas de forma inmutable; `toString()` redacta los datos. |

| Identidad para consulta ANT y caché | `ec.edu.udla.consultas.puntos.domain.Cedula` | Implementada como objeto de valor con validación estructural de 10 dígitos ASCII; no valida dígito verificador ni existencia. No se deriva del RUC. |
| Puerto de caché de puntos | `ec.edu.udla.consultas.puntos.application.port.out.PuntosLicenciaCachePort` | Implementado: recibe `Cedula`, persiste solo resultados `ANT` y recupera opcionalmente el último como `CACHE`, conservando `fetchedAt`. No guarda cédula en payload ni deriva cédulas de RUC. |
| Ensamblaje Spring de servicios de aplicación | `ec.edu.udla.consultas.shared.config.ApplicationServiceConfiguration` | Implementado en la capa externa con métodos `@Bean`; los servicios de aplicación no dependen de Spring. |

| Puertos de vehículos | `ec.edu.udla.consultas.vehiculos.application.port.in` y `ec.edu.udla.consultas.vehiculos.application.port.out` | Implementados para consulta por identificador vehicular. |

| Adaptador ANT real | `ec.edu.udla.consultas.puntos.adapter.out.ant` | Pendiente: no se observó formulario ni respuesta funcional y no hay un parser ni una solicitud HTTP real. La URL investigada menciona citaciones mientras el requisito funcional es total de puntos; no se asumen equivalentes. |
| Adaptador ANT simulado | `ec.edu.udla.consultas.puntos.adapter.out.ant.simulation.SimulatedAntPuntosLicenciaAdapter` | Implementado solo para desarrollo local: escenarios éxito, cero, sin información, timeout, indisponibilidad y recuperación; identifica toda respuesta como `SIMULATED` y no usa red. |
| Adaptador Redis para caché ANT | `ec.edu.udla.consultas.puntos.adapter.out.redis.RedisPuntosLicenciaCacheAdapter` | Implementado y condicionado por `REDIS_CACHE_ENABLED`; usa JSON tipado (`totalPuntos`, `fetchedAt`, `source`), TTL y clave HMAC-SHA-256 v2. Desactivado por defecto; solo acepta fuente `ANT`, nunca `SIMULATED`. |
| Frontend React | `frontend/` | Cliente separado; no pertenece al paquete Java ni llama directamente a SRI, ANT o Redis. |

Las rutas de consulta de contribuyentes y vehículos están implementadas en el adaptador REST. Sus pruebas HTTP son sintéticas; los adaptadores salientes se prueban con `MockRestServiceServer`, sin llamadas reales durante las pruebas automatizadas. El script `scripts/validar-casos-exitosos.ps1 -SoloANT` es una herramienta de diagnóstico, no un adaptador de la aplicación. Para puntos, existe una ruta local de simulación, el caso de uso, el circuit breaker que envuelve ese límite simulado y el fallback al puerto Redis. No existe todavía una llamada real ni un parser ANT; por ello no se ha verificado el fallback con datos del proveedor. La caché guarda solo resultados normalizados marcados `ANT` y nunca resultados simulados.

Los nombres `application`, `adapter.in` y `adapter.out` expresan la separación hexagonal ligera: los casos de uso dependen de puertos y los adaptadores externos los implementan. Las configuraciones externas ensamblan los servicios sin incorporar Spring al dominio ni a la aplicación. Para puntos, el contrato interno solo incluye `totalPuntos` y metadata; no inventa campos ANT. La API de puntos y el adaptador simulado solo están activos en `local-simulation`, enlazado a loopback. El backend continúa siendo una sola aplicación desplegable y sus módulos son límites lógicos.
